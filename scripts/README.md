## Description of directory contents


#### The `dlxy` folders

The main folders of interest are called `dlx.??(.unif_costh)` where `??` is `01 ... 09`. The folders that, in addition, have `.unif_costh` contain a uniformly distributed variable $x_2\sim\cos\theta$. These were generated by unweighting the events in `dlxy.??` folders and thus have less events. Specifically, the unweighting efficiency is $\sim 67\%$.

```bash
.
├── dlxy.00
├── dlxy.00.unif_costh
⋮
├── dlxy.06
├── dlxy.06.unif_costh
├── dlxy.07
├── dlxy.08
├── dlxy.09

```

#### The batches

Each of the `dlxy` folders contains files named `batch.???.dat(.gz)` where, again, `???` is the serial number of the batch. Generally there are 1000 batches each containing 1000 events (so 1M events total per folder). However, because of the unweighting efficiency the last folder with the `.unif_costh` extension does not have 1000 batches and the last batch in it does not have 1000 events.

```bash
dlxy.00.unif_costh/
├── batch.000.dat.gz
⋮
└── batch.999.dat.gz
```

The description of the format of `batch.???.dat.gz` files is given below.

## The format of the 4d helas data

If all 9 helicity amplitudes were written to file (as is the case here), there should be a total of `4 + 9 * 4 = 40` columns in the `.dat` files

  * cols 1 -- 4 : the PS coordinates {sqrts,costh,m3,m4}

  * cols 5, 9, 13, ..., 37: the real part of the classes A+B 2-loop amplitude

  * cols 6, 10, 14, ..., 38: the imaginary part of the classes A+B, ...

  * cols 7, 11, 15, ...,39: the real part of the class C 2-loop amplitudes

  * cols 8, 12, 16, ..., 40: the imaginary part of the class C, ...

Each of the 9 sets of 4 columns corresponds to one of the 9 helicity amplitudes, so cols 5 -- 8 is one helicity amplitude, 9 -- 12 is the next and so on and so forth.

The code used to generate this data is on the `theoc` cluster under `../helamps/`. The main source file is `compute_helamps.cpp` and the relevant code snippet is

